# Agent 보안 기초

## 핵심 원칙

```text
LLM의 실행 제안
≠
시스템의 실행 권한
```

## 필수 기준

- Tool allowlist
- Pydantic 입력 검증
- 사용자별 데이터 격리
- 최대 반복 횟수
- timeout과 retry 제한
- Secret과 개인정보 로그 금지
- 변경 작업 전 Human Approval
- Prompt Injection과 신뢰할 수 없는 문서·Tool 결과 분리
- 인증된 사용자와 요청의 `user_id` 일치 확인
- 승인 요청의 중복 실행 방지
- 필요한 Tool만 허용하는 최소 권한

## 교육 과정 위험 등급

| 등급 | 예 | 처리 |
| --- | --- | --- |
| 조회 | 날씨·정책 검색 | 자동 허용 |
| 초안 | 일정·예약 요청서 생성 | 자동 허용 |
| 외부 변경 | 예약 요청·메시지 발송 | 승인 후 Mock 실행 |
| 결제·삭제 | 결제, 실제 데이터 삭제 | 과정에서 금지 |

## 신뢰 경계

다음 입력은 모두 신뢰할 수 없는 데이터로 취급합니다.

- 사용자의 Prompt
- 업로드한 이미지 안의 문구
- RAG로 검색한 외부 문서
- Tool과 외부 API의 응답
- 이전 대화와 사용자 Memory

LLM이 문서나 Tool 결과에서 명령처럼 보이는 문장을 발견해도 시스템 지시로
실행하지 않습니다. Tool 이름과 인자는 Python allowlist와 Pydantic Schema로
다시 검증합니다.

## 인증과 승인의 차이

```text
인증: 이 사용자가 누구인가?
인가: 이 사용자가 이 기능을 사용할 수 있는가?
승인: 이번 변경 작업을 실제로 진행해도 되는가?
```

현재 `05` Backend의 `demo-user`, URL의 `user_id`, 승인 요청의 `actor`는 인증된
신원 정보가 아니라 교육용 입력값입니다. 따라서 로컬에서만 실행하고 외부
네트워크에 공개하지 않습니다. 실제 서비스에서는 인증 토큰에서 사용자 ID와
권한을 가져오고, 승인 결과와 실행 ID를 함께 기록해야 합니다.

## Memory에 저장하지 않을 정보

- 비밀번호와 API Key
- 카드번호와 결제 인증정보
- 여권번호와 주민등록번호
- 원본 이미지와 불필요한 개인 대화

저장 전에는 Key 이름뿐 아니라 값의 형식도 검사하고, 사용자별 조회·삭제 권한을
분리합니다.
